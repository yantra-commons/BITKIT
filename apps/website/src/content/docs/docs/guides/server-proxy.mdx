---
title: Server proxy pattern
description: Keep provider API keys on your server and let the browser talk only to your API.
---

Payment providers authenticate with secret API keys. Anyone can read JavaScript shipped to a
browser, so those keys must stay on a server. The pattern:

```
Browser                         Your server                      Provider
<bk-checkout>                   POST /api/payments  ───────────► BTCPay / LNbits / OpenNode
  └ HttpAdapter ──────────────► GET  /api/payments/:id ────────►   (API key lives here)
                                ◄─────────────── webhook ──────── marks the order paid
```

A complete, dependency-free example is in
[`apps/examples/proxy`](https://github.com/yantra-commons/BITKIT/tree/main/apps/examples/proxy). The essentials:

1. **Validate input.** Accept whole sats in a sane range. Better still, accept an order id and look
   the price up yourself. Never trust a browser-supplied amount for real goods.
2. **Allow-list routes.** Expose only "create invoice" and "get status". Never forward arbitrary
   paths to the provider.
3. **Restrict ids.** Only accept ids matching `[A-Za-z0-9_-]` before putting them in a URL.
4. **Rate-limit** invoice creation per client.
5. **CORS**: allow only your site's origin.
6. **Fulfil from webhooks**, not from the browser's `bk-paid` event.

```ts title="Browser"
import { createHttpAdapter } from '@bitkit-ui/adapters/http';
checkout.adapter = createHttpAdapter({ baseUrl: '/api/payments' });
```

```js title="Server (excerpt)"
import { BtcPayAdapter } from '@bitkit-ui/adapters/btcpay';
const btcpay = new BtcPayAdapter({ baseUrl, storeId, apiKey }); // fine: this is not a browser

if (req.method === 'POST' && url.pathname === '/api/payments') {
  const v = validateCreate(await readJson(req));
  if (!v.ok) return send(res, 400, { error: v.error });
  return send(res, 201, await btcpay.createInvoice(v.value));
}
```

Amounts travel as strings in JSON (`"21000"`), and the HTTP adapter turns them back into `bigint`.
